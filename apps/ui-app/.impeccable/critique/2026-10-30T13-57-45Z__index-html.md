# Raptix UI critique

## Scope and method

Target: `index.html`, with the styles and dynamic views used by Dashboard, Projects, Vulnerabilities, Chat, and System settings. Reviewed the running demo at 1440×1000 in light/dark themes and at 390×844 in light mode. This is an Operate surface: scanability, context, and execution control should lead. Scores are indicative of these sampled screens; error paths and every product route were not exhaustively exercised. No application code was modified. Temporary review servers were stopped.

## Design specificity verdict

The product model is specific; the presentation is often category-interchangeable. Projects, facts, findings, and execution belong to Raptix, but the pastel KPI tiles, nested rounded cards, glowing chart, and oversized chat greeting could move into almost any AI dashboard. The largest opportunity is to make assessment work—not dashboard decoration—the first thing users see.

## What's working

- Projects connect facts, assets, conversations, and findings in a useful domain structure.
- The dashboard failure banner names a problem and links directly to Monitor/MCP management.
- Text-labeled navigation, active-page highlighting, and substantial light/dark coverage provide a foundation worth retaining.

## Priority issues

### 1. [P1] Summary furniture outranks the actual work

**Evidence:** Five dashboard KPIs receive almost equal emphasis, including token usage and urgent operational metrics. On mobile, all six vulnerability summary tiles appear before search and findings: the first finding starts at approximately y=1051 in an 844px-high viewport. Desktop finding cards are about 114px tall; mobile examples grow to roughly 247–282px. The dashboard severity section repeats the total, chart labels, legend counts/percentages, risk score, urgent counts, status tiles, and remediation progress.

**Why it matters:** Practitioners have to scroll and interpret summaries before reaching evidence or deciding what to investigate.

**Direction:** Put actionable findings and execution failures first. Compress severity totals into a compact filter/summary strip on mobile; subordinate token accounting; reduce redundant encodings; use denser finding rows with expanded detail on demand.

**Sources:** `index.html:478`, `index.html:538`, `index.html:2609`; `src/styles/style.css:23966`, `src/styles/style.css:27440`.

**Suggested commands:** `/impeccable layout`, `/impeccable adapt`.

### 2. [P1] Important context is truncated or visually demoted

**Evidence:** Project names are deliberately shortened to 12 characters. The prominent chat headline displays “Lab Web Peri…?” despite substantial whitespace. The Projects heading is shortened too; fact keys and summaries truncate while four per-row actions occupy a wide fixed area. Settings hint text is measured around 2.0–2.1:1 contrast; project filter labels around 2.6:1. Chat composer guidance and workspace tabs also appear washed out.

**Why it matters:** Users lose project/target recognition and can mistake usable controls or meaningful instructions for disabled content. Hover titles are a weak substitute on touch devices.

**Direction:** Allow full names in primary headings, reserve table width for keys and summaries, move secondary row actions into a menu, and strengthen supporting text to readable contrast. Keep quiet styling without making text disappear.

**Sources:** `src/features/chat/messages/project-name.ts:3`, `src/features/chat/messages/welcome.ts:19`, `index.html:2349`, `src/styles/style.css:24`, `src/styles/chat-workspace.css:78`.

**Suggested command:** `/impeccable typeset`.

### 3. [P1] Color has conflicting meanings

**Evidence:** Red marks primary actions, selected navigation, open status, Retest, export, edit, delete, and the Info severity number. The dashboard chart renders Info blue while its adjacent legend dot is red; Vulnerabilities uses a gray Info rail and a red number. In the risk overview, Low sits in a red-tinted badge. A degraded 75% tool-success KPI retains a teal success/check icon.

**Why it matters:** Operators cannot reliably distinguish urgency, selection, ordinary action, and destructive action at a glance.

**Direction:** Define one mapping for severity across charts, legends, lists, and statistics. Use neutral secondary actions, reserve danger treatment for destructive/error states, and make KPI icon treatment follow actual health. Brand red can remain, but needs separate visual roles.

**Sources:** `src/styles/style.css:21126`, `src/styles/style.css:21224`, `src/styles/style.css:24013`, `src/styles/style.css:26222`.

**Suggested command:** `/impeccable colorize`.

### 4. [P2] Decorative layers make the dashboard feel templated

**Evidence:** A dotted canvas, multicolored KPI gradients, tinted icon squares, layered shadows, rounded cards within cards, hover lifts, glossy chart segments, a breathing chart aura, and bouncing labels all appear together. Several chart values are duplicated in a more legible legend. Four equal tool counts are shown as differently colored bars without a meaningful categorical color mapping.

**Why it matters:** Attention goes to visual treatments rather than differences in operational importance. This is the clearest cluster of generic AI-dashboard patterns.

**Direction:** Keep structural section boundaries; remove ambient chart glow, gloss, decorative bouncing, and the dotted background. Flatten inner status groups and use color where it encodes information. Retain useful data visualization and motion that confirms real state changes.

**Sources:** `src/styles/style.css:23782`, `src/styles/style.css:23981`, `src/styles/style.css:25969`, `src/styles/style.css:26087`.

**Suggested commands:** `/impeccable distill`, `/impeccable quieter`.

### 5. [P2] Screens use incompatible layout and control conventions

**Evidence:** Desktop Chat simultaneously allocates 224px to main navigation, approximately 280px to conversation navigation, and 320px to an empty Workspace panel; only about 616px remains for the central conversation. A large greeting and a layered composer dominate that remaining space. Project tabs, workspace tabs, and settings navigation use different selection treatments. Add fact looks secondary while New project is primary. Mobile settings actions wrap into a tall block above the actual connection fields. The global header shows a project while the findings page initially says All projects, leaving scope interpretation to the user.

**Why it matters:** Users relearn layout and emphasis between adjacent workflows, and secondary panels consume the area needed for work.

**Direction:** Establish shared page gutters, title/action rows, density levels, tab states, and button priorities. Collapse the empty Workspace panel by default, reveal it when it contains useful execution information, and clearly distinguish global project context from page-specific filter scope. Make mobile headers compact and task-led.

**Sources:** `index.html:2290`, `index.html:2294`, `src/styles/chat-workspace.css:19`, `src/styles/chat-workspace.css:92`, `src/styles/project-switcher.css:21`.

**Suggested commands:** `/impeccable layout`, `/impeccable polish`.

## Cognitive load and emotional journey

High cognitive load: five of eight checklist items fail in the sampled views—single focus, chunking, hierarchy, minimal choices, and working-memory support. The shell has 18 navigation entries in four groups; Security Operations alone presents eight destinations. Projects adds six tabs and four actions per fact row. Grouping and progressive disclosure already exist, but do not yet offset the competing decisions.

The error banner provides a reassuring moment because it explains what to do. Confidence falls when users encounter faint instructions, ambiguous color meanings, and shortened project identity. The chat empty state creates a long pause rather than helping the operator specify the next assessment action. Completion states were not exercised, so peak/end quality is not fully scored.
