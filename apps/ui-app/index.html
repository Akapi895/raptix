Blocking rules

Rule syntax and matching scope›

Enabled rules are checked in order; the first match supplies the blocking message. Patterns use RE2 syntax and are validated by the server when saved or tested.

Messages support {match} (matched text), {tool} (tool name), and {rule} (rule name).

Check MCP tool names and arguments before execution and stop matching calls. Human-in-the-loop approvals and tool whitelists do not bypass these checks.

Rules inspect visible call text only. They do not resolve IP ownership, redirect destinations, or file contents read by tools. Domain rules cannot cover every indirect access.

Audit strategy

Whitelisted tools skip approval. In approval mode the Audit Agent only approves or rejects.
