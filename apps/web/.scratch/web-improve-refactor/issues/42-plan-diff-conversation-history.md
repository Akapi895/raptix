**What to build:** Migrate version comparison and history search/pinning using existing canonical plan/conversation read services.
**Blocked by:** 41.
**Status:** resolved
**Owner:** AI history/compare surfaces; sequenced shared trace-source edits.
**Contract:** [execution.md](../execution.md).

- [x] Comparison identifies changes between explicit revisions before approval; pinned versions do not drift.
- [x] History search/pin/unpin is role/scoped with pagination and loading/empty/error states.

- [x] Legacy AI screen consumers are retired incrementally within measured diff limits.

## Evidence

Two typed ADR-0067 read models replaced the screen-side derivation, mirroring ticket 41's pattern:

- `src/features/plans/compare.ts` (new, 129 lines) - the compare read as a feature-local handler over the one database authority: `readPlanCompare` resolves the adjacent revision pair from the `prevPlanId` chain ticket 39's revision transactions maintain ((previous, this) when a predecessor exists, else (this, successor); neither is a `conflict`), and `stepDiff`/`reapprovalNotes` derive the step diff and re-approval notes from those two stored records on every read — nothing persists a diff, so a pinned version cannot drift and the approved plan's stored record is asserted byte-identical after a revision. Scope rules match the plan service (`resolvePlan` now exported for the share): non-member not-found without leaking, cross-project refused with the owning project, factory superseded-scope guard. `PlanCompareService` + `createPlanCompareService`, keys `['plan', scope, 'compare:<id>']` (plan commits invalidate), `PlanCompareError`, `usePlanCompare(id)`.
- `src/features/aichat/history.ts` (new, 181 lines) - the history/provenance read: `listAiHistory` is member-only per project (non-member `not-found` without leaking; `'all'` aggregates only accessible projects — foreign conversations never merged), masks every archived message text through the one `maskSensitive` rule at the boundary (stored record never rewritten), and derives provenance from the same snapshot (plan annotations via message `planId` with `prevPlanId`/`changes`, tool approvals with `toolFacets`, context ROE/assets/agents). Search (`q`), the actor-type filter and audit pagination apply inside the handler with search-independent scope counts; `getAiHistoryRow` resolves one audit row with same-correlation related events (foreign rows `not-found`, cross-project specific reads `forbidden` with the owning project). `AiHistoryService` + `createAiHistoryService`.
- `src/features/aichat/query.ts` - `historyKeys` (`['ai-history', scope, …filters]` view + `['audit', scope, id]` detail), `AiHistoryReadError`, `useAiHistory` (disabled in the aggregate 'all' view; the screen renders select-a-project there) and `useAiAudit`.
- `src/domain/service-factory.ts` - append-style wiring `plansCompare(actor, projectId)` and `aiHistory(actor, projectId)`.
- `src/screens/g-plan.tsx` - ReviewBody's review diff and re-approval notes and the whole compare route (`CompareBody`) now render from `usePlanCompare` with loading (`role="status"`) and refusal states (`No revision to compare` for the conflict kind); the local `stepDiff`/`reapprovalNotes` copies and the unused `PlanTabs` export are deleted.
